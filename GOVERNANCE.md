# Governance

## Roles

- **Maintainers:** release, security and scientific-claim authority.
- **Physics model owners:** maintain equations, assumptions and validation.
- **Software reviewers:** code correctness, API and performance.
- **Validation reviewers:** independent evidence and uncertainty review.
- **Device-data curators:** provenance, licensing and operating conditions.

No author may alone approve both a physics implementation and its empirical
validation for an accepted release claim.

## Decision process

Routine changes use reviewed pull requests. Changes to default physics, public
schemas, accepted device profiles or claim status require:

- a design record;
- two reviewers, including one validation/physics reviewer;
- migration notes;
- updated validation evidence;
- a release note.

## Scientific disputes

Competing defensible models remain selectable. The project records applicability
domains and validation status rather than forcing premature consensus.
